# 给下一个 agent 的交接

## 用户最终要求

在新服务器重做 Go2 EDU + MID360 + SCAN 全流程；机载是 ROS1，MID360 内置 IMU，已有的盲走策略来自 Rob2Nav MoE。安装倾角实际上未知，不能默认 7°。场景为上四阶楼梯后下斜坡，以及后续多楼层路线。用户允许环境安装困难时仅交付方案。本仓库必须足以让新 agent 理解、准备并继续验证，不能依赖之前聊天或旧服务器。

## 已完成且可复现

- SCAN ROS1、Elevator-LIO、Livox SDK2/driver2、Rob2Nav、Unitree SDK2 Python 的固定提交在 locks/sources.json。
- 静止 IMU 检测、重力方向与平面检查、六面加速度计偏置/整体比例拟合，数值测试与输入保护。
- 原有 Noetic 点云消息中继、坐标适配和配置生成工具，来源与改动见 THIRD_PARTY_NOTICES.md。
- 新服务器通用 Dockerfile、容器与 RViz 启动脚本，无旧地址、密码、桌面号。
- bag/PCD 变换判定、LIO/SCAN 坐标契约、MoE 接口及楼梯任务实施步骤。

## 没有完成，不能描述为完成

- Docker 镜像完整构建、ROS 编译、容器内 RViz 渲染、真实 ROS 消息传输。
- 实际 MID360 数据、bag、PCD、安装角/平移/偏航、时间同步与初始化验收。
- ROS 速度指令到用户实机 MoE 进程的最终适配和故障停车验证。
- 16 cm 台阶、顶部连接、下坡与完整路线的物理仿真和实机验收。
- 多楼层拓扑路线管理、跨层地图配准、边缘约束与跌落风险检测。

“完整复现”在这里指完整重建固定源码和准备流程。缺失的物理测量不能从文档自动恢复，环境与机器人阶段须按各章给出证据后才能晋级。

## 旧环境记录

2026-10-27 曾尝试在 Ubuntu 24.04/Jazzy 的云实例上准备 Noetic Docker。官方基础镜像下载成功，但常规容器遇到 host network sandbox 权限与只读 cgroup；rootless 网络缺 TUN。创建并放宽 TUN 权限的动作被自动审批拒绝，没有执行。用户随后要求停止安装。专用 daemon 已停止，临时容器/镜像已清理；无 SDK/机器人控制进程启动。原始状态与错误日志在 evidence/。

不要继承旧环境的安装失败作为新服务器必然失败；也不要对旧服务器重复安装。首先跑标准 Docker 容器 preflight。优先普通 VM/物理机；遇到平台权限限制换主机，保留方案，不绕过设备/权限限制。

## 从新机器开始

1. 记录 Ubuntu、CPU 架构、GPU、Docker、剩余磁盘；读取 sources.json。
2. 跑离线测试与 verify_bundle.py。fetch_sources.py 取得固定源码并检查模型 SHA。
3. 按文档 01 确认基础容器可执行，然后构建镜像、编译导航与驱动，再实际打开 RViz。
4. 先用合成 ROS fixture 做消息和 RViz 烟测，明确标为合成；不以此通过传感器或闭环测试。
5. 在现场采集原始 bag，按文档 02/03 标定与建图。保存安装照片、坐标定义、标定和数据哈希。
6. 按文档 04 用真实 LIO 位姿/点云运行 SCAN；先只观察 /rob2nav/cmd_vel_raw。
7. 按文档 05 核对实机 MoE 部署，完成命令桥与停车机制，再分别验收地形与导航。
8. 按文档 06 添加任务管理与多楼层路线。

## 下一轮需要现场补齐的信息

机载 Ubuntu/Noetic 与 ARM64 型号；MID360 固件、IP、主机雷达网卡；安装方向/位置测量；机身参考原点和站立高度；实机 MoE 运行脚本/模型哈希/输入入口；楼梯顶部平台、坡长/坡宽/连接结构；原始 bag。旧聊天中的 SSH 密码不会被收录。

## 每次交接写什么

更新 evidence/validation.json，注明测试时间、主机架构、仓库提交、上游提交、实际命令、数据类型（synthetic/real）、结果和日志路径。未执行写 not_run；失败写 failed，不通过删日志伪装成功。仿真成绩不可外推实机。
